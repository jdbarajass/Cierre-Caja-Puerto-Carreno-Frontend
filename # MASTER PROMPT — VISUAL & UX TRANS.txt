# 1. PRIMERA REGLA: NO EMPIECES A MODIFICAR INMEDIATAMENTE

Antes de escribir código:

1. Explora completamente el proyecto.
2. Identifica el framework utilizado.
3. Identifica la arquitectura visual actual.
4. Identifica las páginas, layouts, componentes y patrones existentes.
5. Identifica qué componentes son reutilizables.
6. Identifica qué partes son funcionales y no deben alterarse.
7. Identifica inconsistencias visuales.
8. Identifica problemas de jerarquía visual.
9. Identifica problemas de UX.
10. Identifica oportunidades para incorporar movimiento, microinteracciones y storytelling mediante scroll.
11. Determina qué partes necesitan una transformación radical y cuáles solamente necesitan refinamiento.

# 12. RESPONSIVE DESIGN — MOBILE FIRST QUALITY

El responsive NO debe ser tratado como una adaptación secundaria del diseño desktop.

Quiero una experiencia completamente diseñada para:

* teléfonos pequeños
* teléfonos grandes
* tablets
* laptops
* desktops
* pantallas ultra-wide

La interfaz debe conservar su identidad visual en todos los tamaños, pero la composición puede y DEBE cambiar cuando sea necesario.

## MOBILE NO ES DESKTOP EN PEQUEÑO

No hagas simplemente:

desktop → reducir tamaños → apilar elementos.

En mobile debes replantear la experiencia.

Evalúa individualmente:

* navegación
* header
* sidebar
* botones
* formularios
* tablas
* cards
* filtros
* búsqueda
* modales
* dropdowns
* gráficos
* imágenes
* menús
* acciones principales
* contenido secundario

Si un componente funciona bien en desktop pero no tiene sentido en mobile, rediseña SU PRESENTACIÓN, manteniendo exactamente la misma funcionalidad.

---

## MOBILE NAVIGATION

Analiza la navegación existente y determina la mejor solución para móvil.

Puede utilizarse, cuando tenga sentido:

* bottom navigation
* hamburger navigation
* drawer
* compact header
* contextual navigation
* sticky action bar
* floating action
* collapsible navigation

No introduzcas una navegación nueva si la existente puede adaptarse correctamente.

La navegación debe permitir que el usuario llegue rápidamente a las funciones principales.

---

## TOUCH-FIRST INTERACTION

En mobile no existen hover states como en desktop.

Por lo tanto:

NO dependas de hover para comunicar información importante.

Toda interacción importante debe funcionar mediante:

* tap
* swipe cuando tenga sentido
* scroll
* focus
* teclado móvil

Los elementos táctiles deben tener suficiente área de interacción.

Como referencia, las Web Interface Guidelines de Vercel recomiendan objetivos táctiles de al menos **44 px en mobile**.

Evita:

* botones diminutos
* iconos demasiado juntos
* elementos difíciles de pulsar
* controles pegados a los bordes
* zonas táctiles ambiguas

---

## MOBILE FORMS

Revisa especialmente todos los formularios.

En mobile:

* inputs cómodos
* labels claros
* teclado apropiado según el tipo de dato
* spacing suficiente
* errores visibles
* botones accesibles
* evitar saltos inesperados de layout

Los campos de texto deben evitar tamaños que provoquen zoom automático no deseado en navegadores móviles; las guidelines de Vercel recomiendan un tamaño de fuente de al menos 16 px para inputs móviles.

NO desactives el zoom del navegador.

---

## MOBILE TABLES

Las tablas requieren especial atención.

NO permitas que una tabla simplemente desborde horizontalmente sin analizar la experiencia.

Cuando sea apropiado, considera:

* scroll horizontal controlado
* columnas prioritarias
* columnas secundarias ocultables
* transformación de filas en cards
* información expandible
* jerarquía de datos

Pero NO elimines información funcional.

La información debe seguir estando disponible.

---

## MOBILE CARDS

No reduzcas automáticamente todas las cards.

Evalúa si en mobile deben convertirse en:

* lista
* sección
* acordeón
* card compacta
* elemento expandible

La densidad visual debe adaptarse al tamaño de pantalla.

---

## MOBILE MODALS

Los modales desktop no necesariamente funcionan bien en teléfonos.

Cuando corresponda, adapta su presentación a:

* bottom sheet
* full-screen modal
* drawer
* modal compacto

Manteniendo exactamente la misma funcionalidad.

---

## MOBILE SCROLL EXPERIENCE

Quiero que el scroll en móvil sea especialmente cuidado.

Las animaciones de scroll deben:

* ser fluidas
* no bloquear el scroll
* no generar lag
* no provocar movimientos inesperados
* no ocultar contenido
* no interferir con gestos normales

NO conviertas el scroll en una experiencia pesada.

El usuario siempre debe sentir que tiene el control.

---

## RESPONSIVE MOTION

Las animaciones también deben adaptarse al dispositivo.

Una animación espectacular en desktop puede resultar molesta o pesada en mobile.

Por eso:

DESKTOP:
mayor profundidad visual cuando tenga sentido.

TABLET:
interacciones moderadas.

MOBILE:
animaciones más cortas, simples y eficientes cuando sea necesario.

Además, respeta:

`prefers-reduced-motion`

y proporciona una alternativa adecuada para usuarios que prefieran reducir movimiento. Las Web Interface Guidelines actuales también exigen considerar esta preferencia.

---

## SAFE AREAS

Considera dispositivos con:

* notch
* Dynamic Island
* barras del sistema
* navegación gestual
* orientación horizontal

Utiliza correctamente las áreas seguras cuando corresponda.

Ningún botón importante debe quedar oculto detrás de elementos del sistema.

---

## MOBILE PERFORMANCE

El diseño visual debe funcionar correctamente incluso en dispositivos móviles con recursos limitados.

Evita:

* efectos excesivamente pesados
* animaciones JavaScript innecesarias
* listeners de scroll costosos
* imágenes gigantes
* video innecesario
* partículas excesivas
* múltiples efectos simultáneos

Prioriza animaciones basadas en:

`transform`

y

`opacity`

cuando sea posible.

---

## RESPONSIVE BREAKPOINTS

No diseñes pensando únicamente en:

`desktop / mobile`

Utiliza breakpoints basados en el contenido y en cómo realmente cambia la composición.

La interfaz debe funcionar correctamente en tamaños intermedios.

Especialmente:

* 320–360 px
* 375–390 px
* 414–430 px
* tablet
* laptop
* desktop
* ultra-wide

No quiero breakpoints arbitrarios que solamente funcionen en un dispositivo específico.

---

Busca específicamente:

* textos cortados
* botones fuera de pantalla
* elementos superpuestos
* headers rotos
* modales incorrectos
* tablas problemáticas
* imágenes deformadas
* espacios excesivos
* espacios insuficientes
* typography demasiado grande
* typography demasiado pequeña
* elementos imposibles de tocar
* animaciones que generan problemas

---

## REGLA FINAL DE RESPONSIVE
